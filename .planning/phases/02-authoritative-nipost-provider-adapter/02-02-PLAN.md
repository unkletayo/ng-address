# Phase 2 Plan 2: NipostProvider Implementation, Address Mapping, and Test Suite

**Plan:** `02-02`  
**Phase:** `02-authoritative-nipost-provider-adapter`  
**Target:** `packages/nipost`  
**Official Reference:** [docs.postcode.gov.ng](https://docs.postcode.gov.ng/)  
**Dependencies:** Plan `02-01`, `@ng-address/core`

---

## 1. Goal

Implement the `NipostProvider` class conforming to the `AddressProvider` contract using official NIPOST endpoints (`GET /healthz`, `GET /v1/lookup`, `GET /v1/search/reverse`, `GET /v1/search/nearby`), transform official response payloads into canonical `NigerianAddress` objects with `'nipost'` data provenance, and build a test suite verified against official documentation test postcodes.

---

## 2. Tasks

### Task 1: Payload Transformation & Normalization
- Create `packages/nipost/src/transformer.ts`:
  - `transformLookupResponse(payload, rawCode)`: Transform `LookupResponse` (`postcode`, `administrative_address`, `recent_house_address`, `building_use_status`) into `NigerianAddress`.
  - `transformReverseResponse(payload)`: Transform `ReverseResponse` (`unit`, `area`, `district`, `state`, `coordinate`) into `NigerianAddress`.
  - Attach provenance tracking (`source: 'nipost'`) for all resolved fields.
  - Normalize administrative names (e.g. `state_name: "LAGOS"` -> canonical name and code `LA`) using `@ng-address/core`.

### Task 2: Implement `NipostProvider`
- Create `packages/nipost/src/provider.ts`:
  - Implement `AddressProvider` interface:
    - `lookupPostcode(postcode: string, options?: ProviderRequestOptions)`: Queries `GET /v1/lookup?code={code}&level={level}`. Returns normalized `NigerianAddress` or `null` if `valid: false` / not found.
    - `reverseGeocode(coords: Coordinates, options?: ProviderRequestOptions)`: Queries `GET /v1/search/reverse?lat={lat}&lng={lng}&max_distance_m={radius}`. Returns normalized `NigerianAddress` or `null` when `found: false`.
    - `search(query: string, options?: ProviderSearchOptions)`: Queries `GET /v1/search/autocomplete?q={q}` or `GET /v1/search/nearby`.
    - `healthCheck(): Promise<ProviderHealth>`: Queries `GET /healthz` and measures latency.
  - Export public API in `packages/nipost/src/index.ts`.

### Task 3: Comprehensive Test Suite with Official Fixtures
- Create unit tests under `packages/nipost/test/`:
  - `ndaps.test.ts`: Verify NDAPS 5-segment formatting and parsing across valid and invalid samples.
  - `client-guard.test.ts`: Test `ConfigurationError` when secret key is provided in a browser-like environment.
  - `http-client.test.ts`: Test `X-API-Key` headers, status code translations (`401`, `402`, `403`, `429`, `500`, `503`), and backoff retries.
  - `provider.test.ts`: Test `lookupPostcode`, `reverseGeocode`, `search`, and `healthCheck` using mocked official responses for documentation postcodes (`LA-11-W06-TC-10`, `FC-03-B06-AG-12`, `EN-05-V19-CD-22`, `AK-11-I61-ZF-12`, `KN-31-F82-WJ-80`).
