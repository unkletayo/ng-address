# Phase 2 Plan 1: NIPOST Package Scaffold, NDAPS Format Helpers & Resilient HTTP Client

**Plan:** `02-01`  
**Phase:** `02-authoritative-nipost-provider-adapter`  
**Target:** `packages/nipost`  
**Official Reference:** [docs.postcode.gov.ng](https://docs.postcode.gov.ng/)  
**Dependencies:** `@ng-address/core`

---

## 1. Goal

Scaffold the `@ng-address/nipost` workspace package, implement NDAPS 5-segment (`AA-99-H77-BB-55`) format parsing and validation utilities, define configuration schemas supporting official NIPOST endpoints (`https://api.postcode.gov.ng`), and build a resilient HTTP client supporting `X-API-Key` authentication, exponential backoff, rate limiting, and client-side secret guards.

---

## 2. Tasks

### Task 1: Package Scaffolding & Monorepo Configuration
- Create `packages/nipost/package.json` with workspace dependency on `@ng-address/core`.
- Create `packages/nipost/tsconfig.json` and `packages/nipost/tsup.config.ts` (targeting ESM, CJS, and `.d.ts`).
- Verify monorepo installation with `pnpm install`.

### Task 2: NDAPS 5-Segment Postcode Helpers
- Create `packages/nipost/src/ndaps.ts`:
  - `parseNdapsPostcode(code: string)`: Parse 12-character 5-segment codes (supporting formatted `EK-01-A03-FK-01`, display `EK 01 A03 FK 01`, or compact `EK01A03FK01`).
  - `formatNdapsPostcode(segments, style: 'formatted' | 'display' | 'compact')`: Format segments into standard styles.
  - `isValidNdapsPostcode(code: string)`: Fast regex validator for NDAPS syntax.

### Task 3: Configuration & Server-Side Security Guard
- Create `packages/nipost/src/config.ts`:
  - `NipostConfig` interface & Zod validation schema:
    - `apiKey?: string` (supports `nipost_test_...`, `nipost_live_...`, `nipost_pk_...`)
    - `baseUrl?: string` (default: `'https://api.postcode.gov.ng'`)
    - `level?: 1 | 2 | 3 | 4 | 5` (default: 2)
    - `timeoutMs?: number` (default: 5000)
    - `maxRetries?: number` (default: 3)
    - `retryDelayMs?: number` (default: 500)
    - `allowClientUsage?: boolean` (default: false)
  - Runtime check: if `typeof window !== 'undefined'` and `apiKey` is a secret key (`nipost_live_...` or `nipost_test_...`) and `allowClientUsage` is false, throw `ConfigurationError`.

### Task 4: Resilient HTTP Transport Layer
- Create `packages/nipost/src/http-client.ts`:
  - Native `fetch` with `AbortController` timeout handling.
  - Set `X-API-Key` header when `apiKey` is present.
  - Parse rate limit headers (`X-RateLimit-Limit`, `X-RateLimit-Remaining`).
  - Retry loop with randomized exponential jitter for 5xx errors and network failures.
  - Map status codes (`401`, `402`, `403`, `429`, `5xx`) and response envelope `{ "error": { "code", "message" } }` to typed `AddressError` instances (`ProviderError`, `ConfigurationError`).
